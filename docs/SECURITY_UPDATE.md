# 비와 비율 던전: 방별 기록 보호 수정

수정일: 2026-11-17. 브랜치: fix/room-score-access. 기준: f320964.

## 변경

- 전체 공개 순위표를 없애고 개인 화면에는 해당 사용자 본인 기록만 표시한다.
- 서버가 Firebase Custom Token으로 교사/학생 역할과 방 코드를 발급한다. 학생은 방 코드만으로 입장하되 교사 권한은 받지 않는다.
- Firestore Rules는 학생의 본인 기록 생성/수정/조회, 인증한 방 교사의 조회만 허용한다. 전체 조회·다른 학생 기록 덮어쓰기·소유자 변경·방 이동·클라이언트 삭제를 거부한다.
- 기존 ownerId 없는 기록은 해당 방 교사가 읽을 수 있다. 학생이 그 기록을 인수하는 것은 거부한다. 기록 삭제와 전체 초기화는 기존 서버 비밀번호 검증을 유지하며, 인증한 정규 방 코드에 정확히 일치하는 기록만 대상으로 한다.
- 교사 비밀번호 변경 시 accessVersion을 교체해 기존 교사 토큰을 Rules에서 거부한다. 새 비밀번호로 로그인해야 한다.
- 클라이언트의 방 문서 직접 읽기를 금지하고 서버는 존재 여부와 정규화 코드만 반환한다. 교사 이름·과거 평문 비밀번호는 공개 응답에 포함하지 않는다.
- 공통 1234 교사 진입 화면 제거. 새 방 관리 비밀번호는 8~64자로 필수 입력한다. 기존 방의 과거 비밀번호로 기존 방 로그인은 가능하다.
- 학생 실명 안내를 별명 안내로 변경하고, 브라우저 세션 저장소를 사용할 수 없으면 인증은 메모리에 유지한다.
- Vite 빌드의 미사용 Gemini 키 삽입 제거. API 입력 크기 제한과 인증 입력 길이 제한 추가.

## 검증

- TypeScript 검사, 프런트엔드 Vite 빌드, Functions TypeScript 빌드 통과.
- demo-ratio-security 프로젝트의 Auth/Firestore 에뮬레이터에서 보안/API 테스트 18개 통과.
- 비인증 접근, 같은 반 다른 학생·다른 방 접근, 소유자/방 변경, 임의 필드·범위 밖 점수, 전체 쿼리, 기존 기록 인수, 비밀번호 버전 폐기 검증 포함.
- 실제 Custom Token을 Auth 에뮬레이터에서 교환하고 역할·UID 유지·권한 축소를 확인했다.
- 로컬 실제 브라우저에서 교사 방 비밀번호 로그인, 가상 학생 방 입장, 문제 1개 정답 점수, 교사 대시보드 1명/1점 표시를 확인했다. 콘솔 오류 없음.
- 실제 학생 자료나 운영 DB는 읽거나 수정하지 않았다. 운영 보안 규칙이 바뀌었다고 주장하지 않는다.

## 실행

개발 도구 Node.js, Java 21, Firebase CLI가 있는 환경에서:

    npm ci
    npm --prefix functions ci
    npm --prefix functions run build
    npm run lint
    npm run build
    npm run test:security

화면 재현은 첫 터미널에서:

    firebase emulators:exec --project demo-ratio-security --config firebase.security-test.json --only firestore,auth "node tests/ui-server.cjs"

둘째 PowerShell에서:

    $env:VITE_USE_EMULATORS='true'
    $env:VITE_FUNCTIONS_API_URL='http://127.0.0.1:5107'
    npm run dev -- --host 127.0.0.1

시험방 ui-room / 비밀번호 ui-test-pass-2026은 로컬 demo 시험용이다. 운영 계정·비밀번호가 아니다.

## 운영 적용 전 확인 및 순서

로컬 검증 후 사용자가 운영 반영을 승인했다. 최신 적용 상태는 DEPLOYMENT.md를 확인한다.

1. 현재 Cloudflare 배포 커밋, Functions api 및 named Firestore DB가 이 저장소와 대응하는지 확인한다.
2. Functions 실행 서비스 계정의 Firebase Custom Token 서명 권한(signBlob)과 프로젝트의 Firebase Authentication 사용 준비를 확인한다. 에뮬레이터 성공이 운영 IAM 권한을 보증하지 않는다.
3. 새 Functions를 먼저 배포하고 Custom Token 발급·교사 로그인·학생 입장을 가상 방으로 확인한다. 서버 코드는 기존 API도 유지한다.
4. 프런트엔드는 기본 운영 설정으로 다시 빌드한다. VITE_USE_EMULATORS를 설정하지 않는다. Cloudflare Pages를 새 프런트로 갱신하고 운영 가상 방을 검증한다.
5. Firestore Rules를 제한 규칙으로 갱신하고 즉시 비인증/다른 방 차단을 확인한다. Rules 적용 전까지는 기존 공개 접근 문제가 해결됐다고 안내하면 안 된다.
6. 기존 탭 사용자는 새로고침·재입장한다. 예전 프런트는 제한 규칙 적용 후 점수 저장/조회가 실패한다. 작업 중 세션 영향을 안내하고 적용 시간을 정한다.

새 프런트·서버·규칙을 서로 다른 버전으로 오래 운영하지 않는다. 실패 시 취약한 공개 규칙으로 되돌리는 것보다 기록 기능을 임시 중지하고 원인을 확인한다.

## 남은 한계

- 학생은 방 코드를 알고 입장한다. 방 코드 공유만으로 교사 기록을 읽을 수는 없으나 엄격한 재학생 신원 확인이나 PIN 복구 기능은 아니다.
- 학생은 자기 점수만 변경할 수 있지만 점수 계산은 기존처럼 클라이언트가 수행한다. 점수 진위 보증이나 서버 채점은 이번 수정에 포함하지 않았다.
- 호출 제한은 인스턴스별 메모리 기반이다. 분산된 총 사용량 상한이나 과금 한도를 보장하지 않는다.
- 기존 ownerId 없는 개인 기록은 공개 조회하지 않는다. 기존 학급 기록은 해당 교사가 그대로 볼 수 있고 자료를 삭제·마이그레이션하지 않는다.
- 세션 저장소를 차단한 브라우저에서는 메모리 인증이므로 새로고침 후 재입장이 필요하다. 다른 기기에서 학생의 이전 기록 소유권을 복구하는 기능은 없다.
- 실제 운영 IAM/배포/멀티기기와 전체 게임 완주 회귀는 남아 있다. 이번 UI 검증은 로컬 교사·학생 흐름과 1문항 점수 동기화다.
